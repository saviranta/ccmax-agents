## Naming

### Files
- Components: PascalCase (e.g. `UserProfile.tsx`)
- Utilities/hooks: camelCase (e.g. `useAuth.ts`, `formatDate.ts`)
- Pages/routes: kebab-case (e.g. `user-profile.tsx`, `auth/callback.ts`)
- Tests: same name as file being tested + `.test` (e.g. `UserProfile.test.tsx`)
- Constants: SCREAMING_SNAKE_CASE in dedicated constants files

### Code
- Components: PascalCase
- Functions/methods: camelCase
- Variables: camelCase
- Constants: SCREAMING_SNAKE_CASE
- Types/interfaces: PascalCase, interfaces prefixed with `I` only if needed for disambiguation
- CSS classes: kebab-case
- Database tables: snake_case
- Database columns: snake_case

## Code Style

### TypeScript (if applicable)
- Strict mode enabled — no `any`
- Explicit return types on all exported functions
- Prefer `interface` over `type` for object shapes
- Use `const` by default, `let` only when mutation is needed

### Python (if applicable)
- Type hints on all function signatures
- Docstrings on all public functions (Google style)
- Async functions preferred for I/O operations
- Use dataclasses or Pydantic for data models

## Error Handling

- Never swallow errors silently
- User-facing errors: friendly message + error code (no stack traces)
- Internal errors: log with context, propagate to error boundary
- API errors: use the error shape defined in architecture/overview.md

## Testing

- Unit tests in same directory as source file (`ComponentName.test.tsx`)
- Test file structure: describe blocks matching component/function name
- Each test: Arrange / Act / Assert pattern
- Mock external services, not internal modules
- Test names: "should [behavior] when [condition]"

## API Conventions

[Fill in based on stack — REST or GraphQL]

### REST (if applicable)
- Resource names: plural nouns (e.g. `/users`, `/posts`)
- HTTP methods: GET (read), POST (create), PUT (full update), PATCH (partial update), DELETE
- Response shape: `{ "data": ..., "meta": {} }` for success; `{ "error": { "code": "...", "message": "..." } }` for errors
- Pagination: cursor-based, `{ "data": [...], "meta": { "cursor": "...", "has_more": bool } }`
