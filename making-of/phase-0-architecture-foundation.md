# Phase 0: Architecture & Foundation

**Status:** Q&A complete — implementation in progress

## Overview

Build the shared infrastructure that all five top-level agents depend on: project structure, state management, handoff protocol, audit logging, validation, security templates, and the init script that bootstraps new projects.

## Why This Is Phase 0

Everything else depends on this. Without a shared project state format, handoff protocol, and security baseline, each agent phase would invent its own — leading to incompatibility.

## Deliverables

### 1. Project Template

The directory structure created when initializing a new project:

```
~/…/ClaudeFolder/ClaudeProjects/my-app/  # User's project
├── .claude/
│   ├── settings.json                   # Sandbox + permissions (generated)
│   ├── CLAUDE.md                       # Project-specific context (generated scaffold)
│   └── agents/                         # Symlinks or copies of active agent definitions
├── .max-agents/
│   ├── config.json                     # Project config
│   ├── state.json                      # Current phase, progress, active agents
│   ├── artifacts/                      # Typed outputs from each agent
│   │   ├── prototyper/
│   │   ├── architect/
│   │   ├── builder/
│   │   ├── launcher/
│   │   └── researcher/
│   ├── handoffs/                       # Structured agent-to-agent transitions
│   ├── audit-log/                      # Append-only JSONL action log
│   └── checkpoints/                    # Resumable state snapshots
└── src/                                # Actual project code (user-managed)
```

### 3. Handoff Protocol

Each agent-to-agent transition produces a JSON file:

```json
{
  "id": "handoff-001",
  "from": "prototyper",
  "to": "architect",
  "timestamp": "2026-03-22T15:30:00Z",
  "artifacts_produced": [
    "artifacts/prototyper/vision.md",
    "artifacts/prototyper/user-stories/us-001.md"
  ],
  "decisions_made": [
    "Single-page app, no server-side rendering needed",
    "Auth via Supabase, not custom"
  ],
  "open_questions": [
    "Should we support offline mode?"
  ],
  "recommended_next_steps": [
    "Design data schema for user profiles",
    "Define API contract for auth flow"
  ]
}
```

### 4. Audit Log Format

Append-only JSONL with diffs, one file per day. Archive mechanism with 30-day auto-prune.

```jsonl
{"ts":"2026-03-22T14:30:00Z","agent":"builder-frontend","action":"edit","file":"src/App.tsx","diff":"@@ -1,3 +1,5 @@...","turns_used":3,"task":"task-012","status":"success"}
{"ts":"2026-03-22T14:31:00Z","agent":"reviewer","action":"review","task":"task-012","verdict":"pass","turns_used":5}
```

### 5. Deterministic Validator Script

A shell script (`validate.sh`) that checks project state without using an LLM:

- config.json has all required fields
- state.json phase transitions are valid
- Task graph has no cycles, no missing dependencies
- All file references in task specs point to existing files
- Handoff documents have required fields
- No agent is assigned tasks outside its specialization

### 6. Security Template

Per-project `.claude/settings.json` generated by the init script:

- Sandbox enabled with filesystem restrictions (project root + max-agents system dir read-only)
- Network restricted to configured domains
- Deny rules for .env files, secrets, settings.json itself
- Allow rules for common dev tools (npm, git, etc.)

### 7. Init Script

`max-agents-init.sh` — interactive bash script with two modes:

**New project mode:**
- Prompts for project name (kebab-case), description
- Creates folder in `ClaudeFolder/ClaudeProjects/{name}/`
- Scaffolds `.max-agents/` directory tree
- Generates `config.json`, `state.json`, `.claude/settings.json`, `.claude/CLAUDE.md`, `.gitignore`

**Adopt existing project mode:**
- Prompts for path to existing project
- Scaffolds `.max-agents/` and `.claude/` without touching existing files
- Creates baseline snapshot in `.max-agents/artifacts/baseline/` (project structure, deps, key files)
- Adds `.max-agents/` to existing `.gitignore`
- If `.claude/` already exists, merges settings rather than overwriting

## Q&A Decisions (2026-03-22)

### Project Structure
- Projects live in `~/Library/CloudStorage/Dropbox/ClaudeFolder/ClaudeProjects/`
- Kebab-case folder names
- Git repo created manually by user — init script does not set up git
- Agents must work on both new and existing projects

### State Management
- Progress tracked at **task/feature level**, not phase level
- Checkpoints per completed task (most granular — supports overnight builds)
- Checkpoints include full rollback via auto git commits (tagged with task ID)

### Handoff Protocol
- Starting each top-level agent is **manual** (user decides when to start next agent)
- Receiving agent reviews handoff for completeness, alerts user if issues found
- User decides whether to continue despite issues or go back to sending agent

### Audit Log
- JSONL format with **diffs included** (supports troubleshooting + security review)
- Archive mechanism: user reviews and accepts → logs move to `archive/`
- Auto-prune archive after **30 days**

### Security
- **Allowlist-only** network policy: npm, GitHub, Supabase, Vercel
- Agents can **only access ClaudeFolder** — nothing else on the filesystem
- Each agent scoped to its own project directory — **no cross-project access** (user can override via prompt if needed)
- Deny rules for `.env*`, secrets, `.claude/settings.json`

### Init Script
- Bash, interactive prompts
- **No stack selection** — Architect decides the stack
- `.max-agents/` is **gitignored**
- Two modes: **new project** (creates folder) and **adopt existing project** (scaffolds into existing folder, creates baseline snapshot)
